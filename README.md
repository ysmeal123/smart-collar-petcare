# 스마트 목줄 기반 맞춤 급여 시스템

목줄이 잰 행동 데이터로 건강 상태를 추론해, 사료와 영양제를 개체별로 배합해
자동 사출하는 시스템. 대학교 졸업 캡스톤 프로젝트.

```
목줄 (XIAO nRF52840 Sense)          IMU로 행동 분류
        │  BLE
        ▼
스마트 밥통 (게이트웨이)              데이터 중계 + 사료·영양제 사출
        │  인터넷
        ▼
클라우드                             상태 추론 → 안전 필터 → 처방
        │
        ▼
앱 (Android)                        관찰 결과와 처방 근거 표시
```

**지금 상태를 한 문장으로:** 목줄이 행동 이벤트만 보내주면
**"오늘 이 개에게 언제 무엇을 얼마나 줄 것인가"** 까지 전 구간이 돌아간다.
남은 것은 그 이벤트를 만드는 온디바이스 AI와, 계획을 받아 모터를 돌리는 하드웨어뿐이다.

이음매는 두 곳뿐이다.

```
① 온디바이스 AI → 행동 이벤트     계약 확정 (core/telemetry.py)
                     ↓
              [ 전부 구현됨 ]
                     ↓
② 급여 계획 → 하드웨어 사출       계약 확정 (core/plan.py)
```

폐루프가 화면까지 닫혀 있다.

```
관찰 → 이해 → 질문 → 계획 → 검증 → 배식 → 섭취·체중 → 재관찰
```

앱은 **서버가 있으면 서버, 없으면 기기 안의 데모 데이터**로 돈다.
발표 중 네트워크가 끊겨도 화면이 비지 않되, 어느 쪽인지 화면에 표시한다.

목줄이 보낼 것은 `petcare/core/telemetry.py` 에 계약으로 못 박혀 있다.
행동 이벤트(시각·종류·신뢰도·지속시간)와 1분마다의 상태 표본(착용·걸음·배터리)이 전부다.
나머지 지표는 서버가 파생시킨다.

## 실행 방법

### 1. 앱 보기 (제일 빠름)

Android Studio로 `app-android` 폴더를 열고 ▶ Run.

커맨드라인이면:

```bash
cd app-android
./gradlew :app:installDebug
```

**백엔드를 안 띄워도 앱이 뜹니다.** 알고리즘을 돌린 결과가 asset에 들어 있습니다.

> `local.properties`는 커밋하지 않습니다. Android Studio가 각자 PC 경로로 만들어줍니다.

### 2. 알고리즘 돌려보기

```bash
cd petcare
python run_step4.py          # 4마리 처방 결과 + 근거 전체 출력
python -m pytest tests -v    # 테스트 46개
python -m mock.generator     # 센서 데이터 생성 + 축 판정
```

`run_step4.py`가 제일 볼 만합니다. 앱에 뜨는 내용이 터미널에 그대로 나옵니다.

### 3. 목줄부터 사출 명령까지 전 구간 돌려보기

가짜 목줄이 44일치 이벤트를 **실제 수집 경로로** 쏩니다.
게이트웨이가 올리는 것과 같은 형식이라, 펌웨어가 나오면 이 자리에 끼우기만 하면 됩니다.

```bash
cd petcare
pip install fastapi uvicorn
python seed_live.py          # 이벤트 3,600건씩 4마리 → 집계 → 처방 → 사출 명령
uvicorn api.main:app --reload
```

| 엔드포인트 | 내용 |
|---|---|
| `POST /v1/ingest` | 게이트웨이가 목줄 데이터를 올린다 |
| `GET /v1/dogs/dog_choco/dashboard` | 앱이 읽는 대시보드 (asset과 같은 스키마) |
| `GET /v1/feeder/dog_choco/commands` | 밥통이 받는 사출 명령 |
| `POST /v1/feeder/commands/{id}/ack` | 실행 결과 보고 |
| `POST /v1/jobs/daily` | 일일 배치 수동 실행 |
| `/docs` | Swagger UI |

**이벤트로 쏴도 결과가 같습니다.** 피부 99g·오메가3 4알, 관절 240g·관절 3알,
건강함 0알, 급성 긴급정지 — asset 값과 정확히 일치합니다.
집계 코드를 생성기와 서버가 공유하기 때문입니다(`core/aggregate.py`).

## 이 프로젝트가 붙잡고 있는 문제

### 영양제를 파는 회사가 영양제 양을 정한다

사료와 영양제 카트리지를 파는 게 수익 모델인데, 그 양을 정하는 게 우리 알고리즘이다.
**많이 줄수록 돈을 번다.** 이 이해상충을 설계로 막았다.

- 알고리즘이 **0알을 처방할 수 있어야 한다.** 건강한 개에게 실제로 0이 나오는 걸 실증했다.
- **계산 과정 전체를 사용자에게 공개한다.** 앱의 `왜 이렇게 나왔나요?` 버튼이 그것이다.

### 센서로 알 수 없는 건 처방하지 않는다

칼슘과 종합비타민을 카트리지에서 뺐다. 목줄 IMU로는 칼슘 부족을 감지할 수 없기 때문이다.
소화 축도 같은 이유로 **처방 권한을 회수하고 관찰 전용으로 강등**했다.

### 진단하지 않는다

"피부염입니다"가 아니라 "밤에 긁는 횟수가 평소보다 2.5배 늘었어요"라고 말한다.
수의사가 아니고, 한국에서 사료·영양제의 효능 표현은 사료관리법과
동물용의약품등 취급규칙의 규제 대상이기도 하다.

### 남과 비교하지 않는다

이상 신호는 견종 평균이 아니라 **그 개의 평소**와 비교해서 찾는다.
5kg 말티즈와 28kg 대형견에게 같은 걸음 수 목표를 들이대는 건 의미가 없다.
그래서 평소를 배우는 데 14일이 걸리고, 앱이 그 사실을 먼저 알려준다.
