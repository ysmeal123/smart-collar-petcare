# 펫케어 (Android · Kotlin + Jetpack Compose)

스마트 목줄 행동 데이터 기반 사료·영양제 앱.
디자인은 `../DESIGN-apple.md` 의 토큰을 그대로 옮겼다.

## 실행

Android Studio로 `app-android` 폴더를 열거나, 커맨드라인에서:

```bash
cd app-android
gradlew :app:testDebugUnitTest   # 단위 테스트
gradlew :app:assembleDebug       # APK 빌드
gradlew :app:installDebug        # 기기/에뮬레이터에 설치
```

### 빌드·실행 검증 완료

에뮬레이터(Pixel_6)에 설치해 온보딩부터 대시보드까지 실제로 통과시켰다.

```
BUILD SUCCESSFUL
ModelsTest     tests=9  failures=0
ProfileTest    tests=15 failures=0
app-debug.apk  9.97 MB
```

| | 버전 |
|---|---|

| AGP | 8.13.1 |
| Kotlin | 2.1.20 |
| compileSdk / targetSdk | 35 |

`local.properties` 는 이 PC의 SDK 경로를 담고 있으므로 저장소에 커밋하지 않는다.

## 화면

앱을 처음 켜면 온보딩, 이후에는 대시보드로 바로 들어간다.

```
첫 실행  →  온보딩 12문항  →  SharedPreferences 저장  →  대시보드
재실행   →  대시보드
[프로필] →  온보딩 (기존 값이 채워진 채로 시작)
```

### 온보딩

1~8번은 필수, 9~12번은 건너뛸 수 있다.
**건너뛰면 그 사실을 프로필에 남겨 처방 근거에 표시한다.**

| # | 항목 | 알고리즘에서의 쓰임 |
|---|---|---|
| 1 | 이름 | 표시 |
| 2 | 생년월일 | 성장기·노령 판정 |
| 3 | 성별·중성화 | 에너지 계수 |
| 4 | 체중 | RER = 70 × BW^0.75 |
| 5 | 체구 | 노령 기준선 |
| 6 | 체형 | 목표 체중 |
| 7 | 활동 수준 | 첫 2주 계수 초기값 |
| 8 | 급여 횟수·시각 | 사출 스케줄, 길항 성분 분리 |
| 9 | 견종 | 표시 (없어도 전부 동작) |
| 10 | 알러지 | **Layer 0 — 처방 차단** |
| 11 | 수술 이력 | 관절 축 기준선 보정 |
| 12 | 질환·복용약 | **Layer 1 — 절대 금기** |

숫자를 묻지 않는다. 체형(BCS)은 위에서 본 몸통 실루엣 3장을 Canvas로 그려
고르게 한다 (`onboarding/Visuals.kt`). 세 장의 차이는 허리 폭 하나뿐이다.

문항을 채우는 동안 **입력이 처방을 어떻게 바꾸는지 화면에 즉시 나타난다.**

```
생선 알러지    → 오메가3(어유) 제외, 조류 오메가3로 대체
항응고제 복용  → 오메가3 전면 차단
십자인대 수술  → 관절 기준선 하향 (막는 게 아니라 해석을 바꾼다)
```

규칙은 `petcare/core/constants.py` 의 `BLOCKED_BY_*` / `SURGERY_EFFECT` /
`CARTRIDGE_SUBSTITUTE` 를 옮긴 것이다. **판정 권한은 서버에 있고 앱은 표시용 사본이다.**

### 대시보드

```
[흰 면]      헤더 · 활동 링 · 관찰 카드 · 오늘의 식사
[어두운 타일] 활동량 · 수면 · 밤에 긁은 횟수 · 긁은 시간대
[파치먼트]    상태 지표 · 면책 문구
```

타일끼리 간격을 두지 않는다. **배경색이 바뀌는 것 자체가 구분선이다.**

## 디자인 시스템

`../DESIGN-apple.md` 의 규칙 네 가지를 지킨다.

1. **인터랙티브 색은 Action Blue(#0066cc) 하나뿐.** 버튼·링크·선택 칩 전부.
2. **크롬에 그림자를 쓰지 않는다.** 카드는 흰 면 + 1px 헤어라인으로만 구분한다.
3. **장식용 그라디언트를 쓰지 않는다.** 차트 막대는 전부 단색이다.
4. **강조가 필요하면 색을 더하기 전에 면을 바꾼다.**

네 번째를 이상 신호 표현에 그대로 적용했다.

| 상태 | 표현 |
|---|---|
| 평소 | 흰 카드 |
| 관찰됨 | 파치먼트 카드 |
| 급성 이상 | **어두운 타일** |

색맹 사용자에게도 대비가 그대로 남는다.

### 의도적으로 확장한 부분

원본 문서는 마케팅 사이트를 분석한 것이라 '건강 상태'라는 개념이 없다.
데이터 표현 전용으로 두 색만 추가했다.

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `attention` | #c93400 | 평소 범위를 벗어난 지표 |
| `critical` | #d70015 | 급성 이상 |

**버튼·링크에는 쓰지 않는다** — 규칙 1을 깨지 않기 위해서다.
값은 애플 시스템 컬러의 접근성 변형(밝은 배경 대비 확보)에서 가져왔다.

### 폰트

SF Pro는 애플 전용이라 안드로이드에 없다. 문서 권고대로 system-ui를 쓰되
**크기·두께·자간 수치는 전부 문서값을 지켰다.**

- 본문 17sp (16 아님)
- 두께 사다리 300 / 400 / 600 / 700 — **500은 의도적으로 비어 있다**
- 표제 음수 자간

Inter로 바꾸려면 `res/font` 에 넣고 `T` 의 `style()` 하나만 고치면 된다.

## 데이터

`app/src/main/assets/demo_*.json` 을 읽는다.
**백엔드를 띄우지 않아도 앱이 뜬다** — 발표 시연에서 서버 의존성을 없애기 위해서다.

이 파일들은 실제 알고리즘을 돌린 결과다. 다시 뽑으려면:

```bash
cd ../petcare
python export_app_data.py
```

서버를 붙이려면 `Repository.load()` 에 HTTP 호출을 넣고
`AndroidManifest.xml` 의 INTERNET 권한 주석을 풀면 된다.
JSON 스키마는 `GET /demo/{scenario}/dashboard` 와 동일하다.

## 의존성을 최소로 유지한다

차트 라이브러리를 쓰지 않는다. **Compose `Canvas`로 직접 그린다.**
아이콘 라이브러리도 쓰지 않고 이모지로 대체했다.

실제 의존성은 Compose BOM + `kotlinx-serialization-json` 뿐이다.

**Navigation 라이브러리도 넣지 않았다.** 화면이 온보딩·대시보드 둘뿐이라
`MainActivity` 의 분기 하나로 충분하다. 급여 이력·카트리지·기기 설정 화면이
붙는 시점에 NavHost로 바꾸는 게 맞다.

프로필 저장도 상용에서는 DataStore + 서버 동기화지만 지금은
SharedPreferences에 JSON 한 줄로 넣었다. **저장 포맷이 서버 스키마와 같아서
그대로 POST로 옮길 수 있다.**

## 표현 원칙

**진단 언어를 쓰지 않는다.** 관찰된 사실만 서술한다.

- ❌ "피부염입니다"
- ✅ "밤에 긁는 횟수가 평소보다 2.5배 늘었어요"

한국에서 사료·영양제의 효능 표현은 사료관리법과 동물용의약품등 취급규칙의
규제 대상이다. 이 원칙은 UI 문구뿐 아니라 마케팅 문구까지 적용해야 한다.

**처방 근거를 숨기지 않는다.** 영양제 사출량을 정하는 알고리즘이 곧 매출을
정하는 이해상충이 있으므로, 계산 과정 전체를 사용자가 펼쳐볼 수 있게 한다.
`왜 이렇게 나왔나요?` 버튼이 그것이다.

**활동 링의 기준은 '평소'다.** 절대 걸음 수가 아니라 개체별 baseline 대비 비율을
보여준다. 5kg 말티즈와 28kg 대형견에게 같은 목표를 들이대는 것은 의미가 없다.
